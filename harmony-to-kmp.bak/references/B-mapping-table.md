## B. 对照点表（先只读、后改码；硬门）

> 对照原项目实现，禁止用系统组件/未入仓占位顶替设计稿。  
> CODE 前必须先出表；表未过门不准写码。做完用**同一张表**逐行验收。

### B.1 开工顺序

1. 只读源码（逻辑源 + KMP 落点勘察 + 资源盘点），不要写代码。
2. 输出对照点表（每行一个界面对应点）。
3. 任一行「系统替代」「待定」、资源「缺失」未裁定 → **停问**。
4. 用户确认后，**只改表内文件**（白名单外禁止动）。
5. 同表回勾：`一致 | 不一致（差异一句）`。

### B.2 对照点表（每行五列）

| # | 源文件和控件 | KMP/CMP 落点 | 资源 | 时序 | 禁止项 |
|---|---|---|---|---|---|
| 1 | **类名/Compose 或 View/ArkUI 节点/资源路径**（禁「类似弹框」） | **source set + 文件路径**；复用哪个现有 Composable，或新建哪个具体文件 | 要拷贝的文件名；没有则 **「缺失，停止」**；目标 composeResources 路径 | 谁触发、成功后改哪个 State/VM 字段、明确不发生什么 | 本点禁用的系统 API / 错误 source set / 擅自 expect |

列约束：

1. **源文件和控件**：写清源端类/方法/布局 id/`Modifier` 节点/资源路径。
2. **KMP/CMP 落点**：写死 `commonMain/...` 或 `ohosMain/...` + Composable/文件名；禁止「找个差不多的」。
3. **资源**：真实文件名；缺失写「缺失，停止」；禁止系统图标/灰块/网图顶替。
4. **时序**：触发者 → 成功态改哪个状态 → 失败/取消不发生什么。
5. **禁止项**：点名禁用 API/行为；规格未写「用系统」则产品弹框/图标一律禁系统替代；禁止把 Android View 类型写进 commonMain。

**停问条件：** 系统替代 / 待定 / TBD / 类似…；资源缺失未裁定；落点写不清文件或 Composable。

### B.3 改码与回勾

- 只改「KMP/CMP 落点」列写明的文件及表内资源拷贝。
- 交卷同表增加对照结果列。
- 不一致项不得标整单完成。

### B.4 Lottie / 动效专项

| 项 | 必须写明 |
|---|---|
| 何时创建 | 进页 / 点击 / 成功态 / 其它 |
| 播哪一个 | 资源路径（须已入仓或表内要拷贝） |
| 播完切哪一个 | 下一资源 / 静止 / 卸载 |
| 是否循环 | 是/否 |
| 禁止 | 盲 `delay`/`sleep` 当播放结束；无证据的自造 timing |

DEVICE（若获准）先验时机再验观感。

### B.5 字体字重对照

真值 = 截图 + 源端 textStyle。源端 Regular/normal → Compose **不设** `FontWeight.Bold` / `SemiBold` / `Medium`（除非源端明确）。层次用字号/颜色/间距，不臆造字重。

### B.6 与 Must-fix / PROMPT

Must-fix 首段：真值 + 禁区 + 证据。对照点表是 STAGE_A 前置产物。白名单路径 ⊆ 落点列，并与 `SOURCE_SET` 一致。
